# Duri Pick GitHub 이슈 백로그

[PRD](PRD.md) · [API 명세](API.md) · [DB 스키마](DB_SCHEMA.md)

각 블록의 제목(예: `[ISS-001] [BE] 첫 출시 7개 지역의 TourAPI 후보 표본 조사`)과 본문을 GitHub Issue에 복사하고 해당 우선순위 라벨(`P0`, `P1`, `P2`)을 붙인다. 제목의 `[FE]`는 프론트엔드, `[BE]`는 백엔드 작업을 뜻한다. `ISS-###`는 문서와 이슈 제목에 쓰는 식별자다. 등록 후 의존 이슈에 GitHub가 발급한 `#번호`를 함께 적는다.

| 라벨 | 기준 |
| --- | --- |
| `P0` | 첫 출시의 핵심 탐색·상세 흐름과 이를 뒷받침하는 데이터 준비 |
| `P1` | 첫 출시 범위의 최근 조회·주변 검색 및 출시 전 검증 |

## P0 · 핵심 탐색과 데이터 기반

### [ISS-001] [BE] 첫 출시 7개 지역의 TourAPI 후보 표본 조사

**근거** [PRD](PRD.md) · [TourAPI 가져오기](API.md#tourapi-가져오기)

**완료 기준**

- [ ] 첫 출시 지역 7곳(용산, 성수~서울숲, 연남, 익선동, 해방촌, 서촌, 북촌)을 기준으로 지역·카테고리별 수집 가능 건수, 주소·좌표·소개 누락률, 사진 보유율과 이용조건 확인 가능 비율을 기록한다.
- [ ] 관광지·문화시설 중심으로 조사하고 수집 가능한 음식점·카페도 포함한다. 조사 결과를 바탕으로 초기 공개 장소 30~50곳의 목표 수량과 지역별 후보 목록을 검토한다.
- [ ] TourAPI 행정 구역과 서비스 탐색 지역의 차이를 확인하고, 주소·좌표로 배정할 기준과 모호한 경계 사례를 정리한다.

### [ISS-004] [BE] TourAPI 후보 수집 및 재동기화 구현

**의존** ISS-001, ISS-003 · **근거** [API 명세](API.md#tourapi-가져오기) · [DB 스키마](DB_SCHEMA.md#tourapi-수집과-동기화)

**완료 기준**

- [ ] `(provider, external_id)`로 같은 장소를 식별하고 신규 장소와 출처 연결을 한 트랜잭션에서 저장한다. 재실행 시 내부 ID를 유지하고 기본정보와 성공 동기화 시각을 갱신한다.

- [ ] 요청 실패·타임아웃·쿼터 초과 범위를 기록한다. 실패하거나 생략된 페이지에 속한 기존 공개 장소는 계속 조회할 수 있다.

**의존** ISS-004 · **근거** [PRD](PRD.md#데이터와-사진-운영) · [DB 스키마](DB_SCHEMA.md#tourapi-수집과-동기화)

**완료 기준**

- [ ] 이름·주소·좌표·카테고리가 유효하고 탐색 지역이 명확하며 중복 의심이 없는 신규 후보를 `published`로 전환한다.
- [ ] 필수값 오류, 지역 배정 모호, 다른 외부 ID의 유사 장소 등은 보류 사유를 기록한다. 저장 가능한 보류 후보는 `draft`를 유지한다.
- [ ] 재수집 시 기존 상태를 보존한다. 비공개 장소는 목록과 최근 카드 응답에서 제외되며 상세 및 주변 검색의 중심 조회는 `404 PLACE_NOT_FOUND`를 반환한다.

### [ISS-007] [BE] 장소 목록·검색·필터 API 구현

**의존** ISS-003 · **근거** FR-01·02·03 · [API 명세](API.md#필터와-목록)

**완료 기준**

- [ ] `GET /api/v1/places`가 공개 장소 카드와 페이지 정보를 반환한다. `created_at`, `id` 내림차순으로 정렬하고 `pageSize + 1`건으로 `hasNextPage`를 계산한다.
- [ ] 앞뒤 공백을 제거한 검색어로 장소명·지역명을 부분 일치 검색한다. 와일드카드 문자는 문자 그대로 검색하고 빈 검색어는 전체 검색으로 처리한다.
- [ ] 같은 종류의 필터는 OR, 다른 종류끼리는 AND로 적용한다. 실내·실외에는 `mixed`를 포함하고 실내외 필터 적용 시 미분류는 제외한다.
- [ ] 페이지 기본값 1·12와 상한 1,000·30, 검색어 최대 50자, 쉼표 구분 필터를 적용한다. 잘못된 값이나 중복 쿼리 키는 `400 INVALID_QUERY`를 반환한다.

### [ISS-008] [BE] 장소 상세·외부 지도 링크 API 구현

**의존** ISS-003 · **근거** FR-04 · [API 명세](API.md#장소-상세)

**완료 기준**

- [ ] `GET /api/v1/places/:id`가 공개 장소 카드에 `summary`, `overview`, `source`, 주소, 좌표, 확인일, 사진, 지도 링크를 추가해 반환한다. 선택값과 빈 배열은 명세를 따르고 내부 검토 메모는 응답에서 제외한다.
- [ ] 좌표는 JSON 숫자, 확인일은 UTC ISO 8601 문자열로 전달한다. 검증 지도 링크가 없으면 이름·좌표로 카카오맵 위치 링크를 만들고, 네이버지도 링크는 검증된 경우에만 제공한다.
- [ ] 양의 32비트 정수 ID를 검증하고 잘못된 ID는 `400 INVALID_PLACE_ID`, 미등록·비공개는 `404 PLACE_NOT_FOUND`를 반환한다.

**의존** ISS-007 · **근거** FR-07 · [API 명세](API.md#필터와-목록)

**완료 기준**

### [ISS-014] [FE] 브라우저 최근 조회 기록과 화면 구현

**의존** ISS-012, ISS-013 · **근거** FR-07 · [DB 스키마](DB_SCHEMA.md#테이블)

**완료 기준**

- [ ] 상세 화면 렌더링이 성공하면 해당 ID와 조회 시각을 같은 브라우저에 최대 20개 저장한다. 재조회한 장소는 맨 위로 이동한다.
- [ ] 목록 클릭, 프리페치, 상세 실패, 카카오 주변 장소 조회는 기록하지 않는다. 기능용 조회 기록은 DB나 서버 로그에 저장하지 않는다.
- [ ] `/recent`에서 기록 순서대로 카드를 열고 기록을 삭제할 수 있다. API 응답에서 생략된 장소도 이용 불가로 표시하고 삭제할 수 있다.

### [ISS-015] [BE] 카카오 로컬 주변 검색 API 구현

**의존** ISS-008 · **근거** FR-05 · [API 명세](API.md#주변-장소-검색)

**완료 기준**

- [ ] `GET /api/v1/places/:id/nearby`가 공개 상세 장소 좌표로 검색한다. 기본값 `cafe`는 `CE7`, `restaurant`는 `FD6`으로 매핑하고 반경 1km, 거리순 첫 페이지, 최대 10개를 요청한다.
- [ ] 중심 장소와 이름·주소가 일치하는 결과를 제외한다. 거리·주소를 정규화하고 유효한 카카오맵 링크를 전달한다. 결과는 장소 DB에 저장하지 않는다.
- [ ] 성공한 빈 결과는 `200`과 빈 배열을 반환한다. 외부 오류, 쿼터 소진, 타임아웃을 각각 `502`, `503`, `504`로 구분하고 타임아웃 기본값을 3초로 설정할 수 있다.
- [ ] 게시 전에 예상 호출량을 카카오 쿼터와 비교한다.

### [ISS-016] [FE] React 주변 검색 영역과 실패 상태 구현

**의존** ISS-012, ISS-015 · **근거** FR-05 · [PRD](PRD.md#화면-상태와-검증)

**완료 기준**

- [ ] 상세의 ‘주변 장소 찾기’를 열었을 때 카페·음식점을 검색한다. 요청에는 현재 장소 ID와 카테고리를 사용하고 브라우저 위치 권한 요청은 발생하지 않는다.
- [ ] 결과의 이름·주소·거리와 외부 카카오맵 링크를 표시한다.
- [ ] 로딩·결과 없음·외부 오류·한도 초과·타임아웃을 구분한다. 타임아웃 시 재시도를 제공하며 어느 상태에서도 장소 상세와 지도 링크를 계속 이용할 수 있다.

### [ISS-017] [FE] [BE] 초기 공개 데이터와 모바일 탐색 흐름 검증
